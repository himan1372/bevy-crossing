# Need to Read — bevy-crossing disc data coverage

**Status as of 2026-10-14**

What the port reads off the player's own ISO/disc image at runtime, versus
what it still needs to read. Design rule (from `.claude-agents/ROADMAP.md`,
OpenMW model): the engine lives in Bevy, **all content loads at runtime from
the player's own disc** — no disc-derived bytes are ever committed, tests use
synthetic data, and the game must start without a disc (placeholder art +
notice). Real-disc tests read `BEVY_CROSSING_ISO` and are `#[ignore]`d.

A "read" here means: parsed from the disc at runtime by `disc/` or `app/`,
with the consumer system named. File paths are locations on a GAFE01
(NTSC-U) disc — the only region the `disc` crate accepts today.

## Status legend — every entry carries one tag

- ✅ **Read** — parsed from the player's disc at runtime; consumers listed.
- 🔶 **Partial** — some files/variants read, remainder known.
- ⏳ **Needed** — a milestone needs it, no reader yet.
- 🚫 **Not reading** — out of scope, or by design (e.g. hardcoded fallback
  when no disc is present).

## Disc container

- ✅ **ISO/GCM/CISO open** — `disc/src/image.rs`: raw + block-mapped CISO
  images, disc header (GC magic `0xC2339F3D` at `0x1C`, game ID at `0x00`),
  DOL offset at `0x420`, FST at `0x424`/`0x428`, case-insensitive FST lookup.
  Only `GAFE01` accepted (`WrongGame` otherwise).
- ⏳ **RVZ/GCZ containers** — deferred in `disc-setup`; needs new container
  parsers.
- 🚫 **Other regions (PAL/JPN)** — `disc` crate is GAFE01-only by decision;
  would need new game IDs + symbol maps.

## Code & data blobs

- ✅ **`main.dol`** — `disc/src/image.rs` + `app/src/game_disc.rs::load()`:
  18-section table; DOL-resident tables (audio headers) and symbol addresses.
- ✅ **`foresta.rel.szs`** — `disc/src/yaz0.rs` decompresses;
  `disc/src/rom.rs` parses the REL section/relocation tables and resolves
  `R_PPC_ADDR32` data pointers to file offsets (72,924 resolve on disc).
- ✅ **RARC archives** — `disc/src/rarc.rs` (Yaz0-aware), flat file listing
  by name. Used for `forest_1st.arc`, `forest_2nd.arc`.
- ✅ **Yaz0 (`.szs`) decompression** — `disc/src/yaz0.rs`.
- ✅ **AssetCatalog** — `disc/src/assets.rs`: name → (DOL/REL, offset, size)
  from `disc/data/*.sym` (39,861 assets; `foresta.sym` 1.3 MB / 30k+ symbols,
  `dol.sym` 43 KB / 1k+; metadata only, generated by `tools/gen_symbols.py`
  from ac-decomp maps). `rel_bss()` gives bss object offsets (e.g. ground
  texture buffers).
- ✅ **GX texture decode** — `disc/src/gx_texture.rs`: GX → RGBA8 for
  I4/I8/IA4/IA8/RGB565/RGB5A3/RGBA8/C4/C8/CMPR + TLUT
  (IA8/RGB565/RGB5A3).
- 🔶 **DOL-resident display lists** — `rom.rs` already resolves DOL
  addresses (`resolve_dol_addr`), but `disc_gfx.rs` deliberately skips them
  (`UNRESOLVED`). Needed for: ocean waves, misc. dynamic geometry.
  → ⏳ reader work, medium difficulty.

## Rendering fidelity (M3 `render-look`)

These are interpreter/material features over already-read data, not new
disc files — except where noted.

- ⏳ **Runtime segments 1–15** — contents are generated by game code at
  runtime (e.g. segment 12 = ocean wave list), not stored on disc; needs
  logic port. `disc_gfx.rs` skips `G_DL` into nonzero segments.
  Medium-hard.
- ✅ **Fog** — applied only to parts whose list keeps `G_FOG` with a `G_BL_CLR_FOG` blender (emu64), over `GX_FOG_PERSP_LIN` eye depths (board 2026-10-13).
- ⏳ **TEV second tile (TEXEL1), blender modes, noise, LOD** —
  medium difficulty. Known gaps in `completed/tev-materials.md`.
- ⏳ **Palettes set by game code** — palettes are computed at runtime, not
  stored; needs the palette-selection logic ported or tables extracted.
  `disc_gfx` currently needs a `--pal` override. Listed as a known gap in
  `completed/gx-backend-bevy.md`.
